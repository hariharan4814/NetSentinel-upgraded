GET STARTED IN FOUR STEPS

Less guesswork. Useful local evidence.

  1. Observe. Select your adapter and authorize metadata capture. Start a download in your own app. If Npcap or permissions are missing, fix the prerequisite; the app will not fill the view with demo data.
  2. Understand. Review application usage and unassigned traffic. Numbers only cover the selected adapter while observation was active.
  3. Choose. Set a quota for a non-critical app. For blocking or scans, explicitly start the privileged broker as described in the installation guide. Web servers never need administrator rights.
  4. Share carefully. Download a redacted PDF for troubleshooting or your project demonstration. The public website separately offers internet checks; it cannot access this dashboard.

Stop and recover

Stop observation in the Overview. Switch to observation-only mode to remove NetSentinel-owned rules. Use the installed Stop script to close the companion. If it crashed, run the broker's recover command before uninstalling. Never reset your whole firewall.

What this solves

Identify which observed applications consume data, set transparent data-use reminders, inspect Windows protection status, and collect evidence for connection problems. It is not an antivirus replacement, a billing meter, or proof that traffic is malicious.

Retention and privacy

Usage: 90 days. Flow metadata: 7 days / 10,000 rows. Control history: 90 days / 2,000 entries. Reports export at most 500 events and flows. No payloads, passwords, cookies, messages or browsing URLs are stored. No automatic provider lookup is performed here.
